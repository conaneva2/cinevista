# 幕野 v0.6｜Film Studio 调研与原生颜色持久化修订

日期：2026-09-19。性质：需求、架构、验收与项目规则修订；不是新增相机驱动或已通过机测的版本。

## 1. 用户要求成为明确验收条件

**在 Mac 导入样张、实时看着效果调色；将一个受支持的原生外观写入 A7R II 后，退出幕野，正常关机重启，不再启动幕野，直接使用索尼原生拍摄，JPEG 仍带该外观。**

这是首版主产品目标，不是开机后让 App 自动启动、后台服务重新套色，或只记住上次的配方名称。生产发布要验证具体机身、固件、外观参数与拍摄模式组合。当前没有 APK 和相机实测，不能宣称已实现。

v0.5 的实时软件调色有效地实现了电脑端的实时像素预览，但其“相机 App 拍后执行 LUT”主路线不能独自满足这个要求。ADR0010 的执行后端优先级由 ADR0011 替代；实时预览、模块化、原片保护、离线和 MIT 开源方向不变。

## 3. 一个需要纠正的运行环境假设

该 a7R II 分支报告 Android 4.1.2 / API16；其 a5100 报告 Android 2.3.7 / API10。此前将所有 PMCA 机身统一描述为 API10 不准确。[F01][F02]

幕野可继续保留兼容 API10 的基础构建，但这是项目最低兼容目标，不是对用户相机实际系统的测量。探针应读取并记录真实 SDK_INT、版本、机型、固件和显示行为；用户这台 A7R II 当前仍未知。可选 API16 路径以后隔离编译/加载，不能因为一份第三方报告就直接提高 minSdk 或调用新类。

硬件预览可能独立于普通 Android UI 合成。即使设备确为 API16、有 TextureView，也不证明 CameraEx 的实时内容能成为普通可变换纹理；Film Studio 记录了常规截图无法抓到预览 overlay 的情况。[F02]

参考开发环境为 Apple Silicon/macOS（参考平台）。不要求换电脑。若采用 Recipe Lab 式 JNI 持久化，需要另行鉴定相机 ABI、NDK、链接库和签名；纯 Java 探针的可构建性不等于已获得该通道。Mac 原生开发＋必要时固定 Linux 构建仍是候选路线。

## 4. 三种颜色后端必须分别标记

| 后端 | 外观在哪里执行 | 重启后不进入幕野直拍 | 决策 |
|---|---|---|---|
| 原生持久化 CS / PP 等已验证设置 | 相机原生拍摄流程 | 目标能力，需逐项实测 | 主线，先做最小原生参数集 |
| 运行时矩阵＋曲线 | App 配置的 ISP 路径 | 当前没有可用持久化证据 | 研究/增强能力，不冒充主线完成 |
| 软件 LUT | App 拍后像素处理 | 该处理本身不能在 App 不运行时执行 | 保留自由调色与增强出片，不作为原生持久化验收替代 |

Recipe Lab 源码中，持久化由 Backup 写入和同步完成；应用退出时还要避免旧运行时值覆盖刚保存的值。App 私有的收藏/上次选择记录与相机实际设置是不同数据。[F03][F04]

A7R II 官方文档列出可定制的 PP 参数及照片/录像共享关系。这证明菜单能力存在，不证明我们已实现 App 读写，也不证明任意曲线/矩阵可写成可被原生开机流程加载的数据。[F07]

## 5. Studio：保留实时调色，不以参数表替代

正式默认创作目标改为“原生直拍”。操作仍是导入样张、实时调色、对照、导出；技术上必须同时解决**相机可表达的范围**与**电脑预览的可靠性**。

### 5.1 两个预览结果，不偷换效果

- **创作目标预览**：允许自由 LUT 编辑，展示用户希望得到的外观。
- **原生适配预览**：使用实际准备写入的受支持参数及相机标定模型渲染，明确显示“估计/已标定范围”。无法复现的效果不能隐瞒。

“原生直拍”工作流应优先操作已验证、可保存的参数域；未映射的自由 HSL、曲线或空间效果不得静默截断后当作相同外观导出。用户从自由编辑转原生目标时，显示并比较适配结果，允许拒绝这个近似。

当前软件渲染器不具备 A7R II 原生流程标定，不能把现有滑杆换个标签就当成原生调色器。**未建立可信模型时，原生发布入口保持未就绪；现有实时软件工作区可继续使用，但明确不是重启直拍成果。**

### 5.2 为什么需要机身标定

普通 JPEG 已经过相机的颜色与明暗处理。Mac 对 JPEG 施加一个变换，和改变拍摄前/成像中的白平衡、Gamma、颜色模式，不天然相同。Film Studio 的 LUT 参考拟合与色度标定是研究线索，不是对全部机身、光线和普通 JPEG 的精确仿真证明。[F01][F02]

拟议标定流程：固定拍摄基线，记录曝光、WB、DRO/PP、场景光线；拍摄灰阶、色卡及独立肤色、植被、天空场景；用部分样片拟合可用参数响应，另外保留独立验证场景。区分照片噪声、AWB变化、镜头/光线变化与算法误差。

使用成熟数值/颜色组件评估拟合误差；初期不预设一个漂亮的 DeltaE 数字。先明确输入、色彩空间、测量方式和场景覆盖。工程内的 LUT 数学往返测试不能转成相机外观准确度。

### 5.3 无损与近似的边界

原生参数集的表达能力有限；3×3 矩阵加共同曲线也不是任意逐色相 3D 映射。我们会尝试寻找满足用户审美的原生配方，而非承诺任何软件 LUT 都能精确永久写入。

无法原生表达的效果仍可保存为 App 增强版。必须由用户看过差别后选择，不能强制把所有自制颜色降级成后台软件处理。

## 6. 一次写入，之后正常开机拍摄：产品流程

目标操作：Studio 完成原生适配 → 导出原生配方数据 → 幕野导入 → 展示目标机身与实际变更 → 用户确认“设为机身直拍颜色” → 执行经验证的保存 → 退出 → 正常重启 → 不进幕野拍摄。

“下载成功/写文件成功/读回成功/重启直拍通过”是四个不同状态。文件只记录语义参数、来源、目标机型、版本、基线和必要哈希，不携带任意硬件地址或脚本。Studio 作者不能通过填写 verified 自证机身兼容。

### 发布协调器的拟议步骤（不是已经实现的索尼事务 API）

1. 核对型号、固件、当前模式、色彩路径和可写白名单；不匹配就拒绝。
2. 展示将改动的必要字段。曝光、文件格式、PP活动槽位各自明确，不悄悄关闭 RAW 或覆盖用户所有 PP。
3. 读取并备份这些必要字段；保存恢复记录，不盲目备份/重写整个相机设置区。
4. 执行已理解的持久化写入，按已验证流程同步，再逐项读回。
5. 退出时保留**刚发布的状态**；未确认的临时预览才按约定恢复。不能把发布前快照无条件写回而撤销本次发布。[F03]
6. 首次通过相机自身可见菜单与原生 JPEG 检查实际效果；正常关机重启后，在不先进入 App 的情况下重复拍摄。
7. 写入失败与恢复失败独立报告。软件日志和临时文件不能保证底层多字段写入是原子的；异常中断的恢复需要实测，不能称零风险。

如果系统保护不允许写入，保持阻断并记录；不自动解除保护、写猜测的地址、刷固件或启用自启动服务来绕过产品要求。

## 7. 如何模块化而不重造工程

保留已有 core、sony、camera-api、app、studio。以下是新增职责/接口设计，不是已实现的 Sony 类：

| 职责 | 输入/输出 | 禁止事项 |
|---|---|---|
| ColorCapabilityProfile | 型号/固件/路径 → 可表达、可预览、可持久化、已测模式分别记录 | 方法存在或返回 false/true 均不单独等于验收 |
| NativeLookCompiler | 创作意图 → 受限有效参数、近似说明、参数指纹 | 不无损“魔法转换”任意 LUT |
| NativePreviewModel | 基线样张＋有效参数 → 标定范围内估计图 | 不把未标定模型称相机精确输出 |
| NativeColorStore | 受审查的必要参数读/写/同步 | 不接收来自配方的任意地址 |
| PublishCoordinator | 备份、确认、写入、读回、恢复策略 | 不用 App 内收藏代替机身保存 |
| VerificationRecorder | 应用退出/重启后的原生样片与模式证据 | 不用 App 再启动重套色替代测试 |

运行时“参数回读”不等于像素生效；Film Studio 记录的能力返回与实际行为相反就是提醒。特殊机型试验可单独立受控探针，但不据此让生产分支对全机型无条件写入。[F02]

## 8. 首轮验证：先把主要求证明出来

第一组使用最小、效果明显且符合 RAW 策略的已知原生颜色参数，暂不叠加任意曲线、复杂软件滤镜和反挤压。选择该参数集是为检验持久化，不是限制最终审美。

验收顺序：正常原生基线 → 幕野写入候选 → 退出后原生拍摄 → 等写卡完成、正常关机 → 开机后不启动幕野直接拍摄 → 核对模式、设置和 JPEG → 备份恢复 → 再次原生拍摄。

每项都记录型号/固件、APK指纹、原生拍摄模式、文件格式、镜头、曝光/WB、参数与样片。至少覆盖约定的 P/A/S/M；AUTO、Scene、MR、用户切换 PP/风格可能覆盖当前外观，应单独记录，不把可预期的用户切换说成永久锁定。

首轮拟议重复 3 次正常关机开机，数量只是测试计划，当前 0 次执行。先拍“重启后原生照片”，最后再进 App 读诊断，以免进 App 重新施加颜色污染证据。

矩阵/曲线持久化独立验证；这条没通过不阻止继续寻找原生 CS/PP 配方，但也不能给矩阵外观贴“原生重启有效”标签。全尺寸视频和所有帧率另验，不以照片通过推定。

## 9. 原生持久颜色不等于幕野全部功能常驻

颜色由机身原生配置维持的部分，可以以不进 App 为目标。65:24 自定义构图、移框、实时反挤压、拍后裁切/软件 LUT 仍按幕野运行期间的功能规划。不能因为颜色保存成功，就声称原生拍摄也自动输出幕野裁切/反挤压照片。

用户改回其他 CS/PP、切换已保存的模式或重置相机，可能替换外观；“持久化”不是永久锁死，也不写保护用户的后续正常操作。

## 10. 开源复用决策

Film Studio 默认新增内容为 PolyForm Noncommercial 1.0.0，是非商用源码公开许可；LICENSING 也区分了 Apache 上游与 Sony 基础 APK、富士/徕卡 LUT 的权利。不能复制这些新增代码到幕野再统一标成 MIT。[F06]

本轮只阅读公开说明以核对技术事实和许可边界，**未复制 Film Studio 原创代码、拟合参数、LUT、官方 APK、字体或图片进入工程**。复用优先级：Recipe Lab 的 MIT 范围 → OpenMemories 接口与平台组件 → 经逐文件核查的 Apache 上游，保留许可证与修改通知。不把发布在 GitHub 当授权证明。[F04][F05][F06]

幕野自己的实现与用户自主创作颜色走独立来源；用户颜色的许可不因工具 MIT 而自动变成 MIT。涉及不明第三方素材时另审，不以“仅个人研究”替代未来公开分发的许可条件。

## 11. 本轮交付与边界

本轮更新主入口规范、代理规则、颜色路线、上游台账、ADR、发布门禁和设备验证模板；为工程规范补充主机测试。原有实时软件调色保留，页面明确标记不能实现重启后原生拍摄生效。

没有新增硬件写入代码，没有连接相机，没有生成 APK，没有标定原生预览模型。现有软件颜色算法和相机 Java 代码保持不变。主机测试通过只证明这些规范和现有主机逻辑，不证明持久化能力。
