# CineVista 研究与开发手册

更新：2026-10-23。对象：Sony A7R II / ILCE-7RM2，官方固件 4.01。本文把分散的实验记录整理成可继续工作的知识入口；原始证据编号见[资料索引](EVIDENCE.md)。

## 先读这一页

我们的长期目标是在相机上实现实时反挤压：一条路线改变取景显示，另一条路线在原生录像编码前处理画面。当前第一步是建立电脑上的虚拟相机，使应用的安装、启动、中断和重启问题可以先在可回滚环境里检查。

**已有成果是最小 Linux、部分原 Sony 服务初始化、虚拟闪存底层持久性、安装方法回放和相机背面操作台。完整 Android 桌面、原生显示输入及 APK 安装后的冷启动验证仍未完成。** 目前没有足够证据保证真实机身安装安全，也没有证明实时反挤压录像的吞吐量。

## 两个主要阻断

**图形：** 已知道软件怎样提交命令、等待并传播完成，但仍缺 Sugilite 实际访存结束、缓存排空、端口状态和 IRQ76 之间的准确规则。向等待处返回成功或者直接发中断，会破坏实验可信度。

**存储：** 已追到主 CPU 与 BOSS 的共享内存、加载入口和握手，但仍没有匹配 4.01 的 BOSS 执行程序及充分的加载依据。普通 NAND 写入持久化不能代替这部分，也不能使原生文件系统自动可用。

两者共同影响原生窗口、Android 与持久安装环境。G08/G10 保留阻断状态，完整模拟器仍是目标；这份手册不是完成声明。

## 如何理解证据

- **运行观察**：指定输入、构建和实验条件下实际看到的行为；不能自动推广到所有模式或真实相机。
- **静态确认**：原文件、指令、符号、重定位或表项支持的结构；不代表相关分支已运行。
- **外部资料**：原作者或厂商公开说明；注明版本和适用机型，并与 4.01 对照。
- **候选 / 未知**：可继续验证的方向或缺口，不填成“已支持”。

特别注意：`返回 0`、驱动加载、文件存在、进度 100%、主机测试通过、EGL fence 变为 signaled，分别有自己的语境，任何一个都不能单独证明相机安全或 GPU 正确执行。
