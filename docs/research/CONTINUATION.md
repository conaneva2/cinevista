# 接续开发与验收指南

更新：2026-10-25。首要目标仍是能够运行原固件与应用的虚拟相机。下一轮从明确缺口继续，不重新搜索已经确认的共同 DMP 库，也不以主机 UI 代替固件开机。

当前执行推进仍缺匹配GPU访存/端口/IRQ规则，以及可验证的BOSS执行端。原程序路线缺匹配4.01载荷和加载依据；R26新增完整协议模型的研究候选，但语义与验收尚未闭合。没有可据此宣称启动推进的新模型，不能重复启动或强行返回成功。

恢复执行建模需要可验证的新输入：匹配硬件规范、可靠实现/已有正常离线执行轨迹、BOSS载荷及加载元数据，或经过逐项验证的完整BOSS协议语义。它们仍须与4.01原文件核对，不要求操作相机或获取用户没有的备份。弱常量命中不能作为程序。完整目标与下方全部验收门槛保持。

1. 读[手册总览](README.md)和[项目状态](../../PROJECT_STATUS.md)顶部，确认当前通过范围与暂停边界。
2. 读[技术链路](TECHNICAL.md)，按工作对象选择 GPU、BOSS、窗口或录像链。
3. 在[证据索引](EVIDENCE.md)定位最近有效 run-id，检查对应输入身份、FINDINGS、SESSION 和 validation；公开仓库没有原始固件证据目录。
4. 读[任务板](../../TODO.md)：G08/G10 仍阻断，T11 的实时反挤压没有因此变为可用；文档任务完成不改变这些验收结果。
5. 核对当前工作树和实验输入，先记录基线，再做一个有明确预期的改动。已有失败对照和未提交工作不能覆盖。

## 2. 无需相机的入口

在项目根目录、已有合法工具链环境中运行：

```sh
python3 tools/cv.py doctor
python3 tools/cv.py check
python3 tools/docs_check.py --write
```

`doctor/check` 不自动安装依赖；`--write` 只从任务板生成文档视图。检查依赖 Python 3.10+、可用 JDK 和 Node，确切版本见[工具链说明](../03_ENVIRONMENT.md)和本机运行记录。不要把机器缺工具误判为产品故障，也不要为消除错误降低门禁。

背面操作台入口：

```sh
python3 tools/virtual_camera.py --port 8765
```

只有已有匹配私有输入时，启动按钮才可创建实验。`config/virtual-camera.lock.json` 校验输入和哈希；公开仓库不包含固件、实验介质和 QEMU 二进制，不保证开箱即用。默认操作台绑定较早的已固定实验，独立图形探针的后续进展不会自动改变默认按钮。按钮目前控制宿主页面，不是原生按键事件。

已有 QEMU 源码补丁在公开仓库的 `emulator/qemu/`，应按目录说明应用到固定基线；本机私人工作区的实验补丁按 R06/R07/R12/R13 查找。不要在文档任务中自动构建、下载或启动客体。

## 3. 下一批可实质推进的工作

| 顺序 | 明确问题 | 优先输入/入口 | 合格产物 | 停止条件 |
|---|---|---|---|---|
| A | 在确有新提交类型或不同映射时扩展CPU侧缓存核查 | R24 已验证MA入口与首提交窗口，R21映射 | 新路径的参数、可见性及覆盖范围；保留用户/内核调试区别 | 不重复已核实的首包地址，不把当前零命中推广到所有路径 |
| B | 更高层窗口 queue/cancel 如何连接 GPU fence | R22 已核实原生命令 1/2 仅维护锁字段；继续追其上下游 | queue/cancel、帧所有权与 GPU fence 的连接；私有格式布局继续待证 | 不在已核实的锁处理体里重复寻找 GPU 完成，不改特殊早返回 |
| C | 哪些 GPU 事务完成后可以发 IRQ76 | 原提交/状态消费与新增匹配规范或正常轨迹 | 逐条命令副作用、访存顺序、端口/状态触发和错误条件，可写为最小模型契约 | 仅有 PICA 近似或同名寄存器时仍保留未知 |
| D | 匹配 BOSS 程序从哪里加载 | 原 lld、loader_writer、pformat normal/safe、设备信息与归档目录 | 实际来源、型号版本、hash、载荷布局、加载与握手条件 | 不把另一机型载荷或随机代码当匹配程序 |
| E | 真实存储与窗口依赖闭合后推进 Android | 原 init 顺序、窗口/图形、FTL 与分区 | 原窗口及 SurfaceFlinger/system_server/启动器的独立运行记录 | 缺服务明确失败，不引入恒成功替身 |

A/B 已有 R21 客户端与映射观察，以及 R22 原生锁服务端静态合同。实际 cache 调用、更高层窗口队列和 GPU 完成仍未闭合；当前启动先遇到 GPU 首提交，不能把服务端静态可读当成已运行通过。原生 `libObj` 的内嵌函数必须单独验证，不能只分析 Android 同名库便解释当前原生停点。

R24 已补全 R23 的核验：原MA入口地址正确，在内核调试上下文可读；限定首提交窗口零命中，命令与对象RAM读回吻合。下一优先级转为 C 的GPU完成条件，B 的高层窗口联系和 D 的BOSS来源可独立推进。只有出现不同缓存路径的实际证据时再扩展 A；保留 R23 失败，不覆盖复跑。

社区检索先读台账，固定提交并比较新增内容。检索不到必须写清范围；不能扩张为“永远不存在”。用户已说明没有现成引导区离线备份，不反复索要，也不通过操作相机补取。

### R34后的优先级

R34新增Altera官方Arria 10命令DMA定义：0x7c0/0x7d0为通道错误与使能的对应线索；0x780 bit8控制出错后停队列。两机相应原指令一致，但4.01恢复参数实际写0x780=0x10，不能套用参照默认值或擅加停队列规则。14项静态核对，无新客体测试。详见技术链路5i。

下一步需闭合生产端：Sony紧凑CDMA对应版本、0x7c0错误与0x720 bit1完成的共存规则、数据及描述符总线写回完成点、ECC码字/位序和metadata保护范围。数据DMA、命令DMA、空闲和错误IRQ应分开核对。现有QEMU缺7c0/7d0模型，但只有候选寄存器名不足以决定其完整执行语义，保留strict-ecc。

R33的26项静态检查和38项状态消费者用例不必重跑；R32的5项逻辑传输也不必重复。extra bit3及第6–7字节仍未知。BOSS候选0；A6000资料HEAD仍6984ce85198ec22bedbf87d69f1c374b96473eb0，R33缺失patch的7文件未全文排除。仅沿新增且相关来源查找，程序必须核对加载范围、邮箱和52字节info。

原生存储、GPU、窗口、Android/APK均未通过。有新的执行依据或明确观察目标再启动，不把静态对照、片段执行或逻辑介质当完整启动。用户无现成离线引导备份，不反复索要，不操作相机。

继续对BOSS协议模型做可行性取证：从两机对应的18类操作恢复布局，重点查4.01的读页/extra/ECC、初始坏块、错误返回和PBM版本字段来源。先形成可复核的输入输出与状态规则；缺字段明确阻断，不能借用A6000数值。只有合同闭合后才考虑独立实验模型，原驱动挂载、正确文件内容、写擦、失败恢复及独立冷启动保留分别验收。此项仍为候选，不是已采用架构或完成声明。

同时保留原BOSS载荷路线。GPU只继续筛选新增且匹配的规范/实现/已有正常轨迹；最低证据是四条尾命令对应的访存效果、端口状态、mask/ack与IRQ76顺序。不要重复下载相同DMP库，不以累计IRQ数或软件fence状态填补硬件合同。允许有明确观察目标的隔离启动测试；区分默认与条件配置，保存超时和观察器失败，不以假响应推进。无相机访问或对外联系。

## 4. 模拟器达到“可用”必须通过什么

| 门槛 | 通过所需证据 | 当前 |
|---|---|---|
| M1 最小 Linux | 原内核进入 shell，输入 hash 与启动条件固定 | 限定实验已通过 |
| M2 底层虚拟存储 | 实际写/擦、关闭整个进程、重新启动后读回 | 合成控制器实验已通过 |
| M3 原生持久存储 | BOSS/FTL 初始化、分区挂载、文件写入与独立冷启动保留 | 未通过 |
| M4 GPU 执行完成 | 预期内存效果、对应状态/IRQ、原驱动消费；错误时不假完成 | 未通过 |
| M5 原生显示输入 | 固件窗口像素可见、原生按键能改变状态 | 未通过；网页外壳不是此项 |
| M6 Android 桌面 | 原 system_server/SurfaceFlinger/启动器稳定运行并可追日志 | 未通过 |
| M7 APK 生命周期 | 固定原样本/对照样本安装、启动、退出、卸载、独立冷启动 | 未通过 |
| M8 故障与恢复实验 | 指定安装中断、存储失败和同步错误可重复，恢复虚拟快照可解释 | 仅局部回放覆盖部分条件 |
| M9 硬件约束 | 内存/存储按证据限制，时钟和外设行为可校准 | 部分容量约束，真实性能未校准 |

APK 能启动也不等于相机功能正常；存在替身或缺模型的地方必须列出。即使 M1–M9 在指定条件下通过，也不能保证真实机身不变砖，事故机真实状态与未建模硬件仍可能不同。

## 5. 实时反挤压恢复开发的门槛

模拟器是当前优先任务，录像研究保留独立待办：验证录像帧到 SDF 票据的所有权转移、YC 与像素单元引用、COMP 到编码接收的帧关联、停止/错误排空、时序和格式继承。只有这些闭合后，才有依据讨论具体桥接实现。

性能还需有匹配硬件的依据。不同分辨率、帧率、倍率、画布和显示并用条件分别验收；不把 GPU 能创建窗口当 DSP 能实时缩放，也不把处理一张图当连续录像通过。当前仍不操作相机。
