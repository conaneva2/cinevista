# 探索时间线与结论修订

更新：2026-10-23。这是一条“问题 → 工作 → 证据 → 新问题”的研究路线。日期按项目交接记录；证据 ID 中的 `Z` 表示 UTC，同一天在本地时区可能跨日。编号对应[资料索引](EVIDENCE.md)，不表示整机验收次数。

## 1. 应用原型与安装事故：先停下真实机身试错

早期工作建立了 API10 / DEX035 / v1 签名构建基线、相机探针、主机几何逻辑、Studio 调色原型及 UI。产品要求后来明确为中文界面、保留原片、真实倍率与成片画幅分离，以及退出应用和重启后仍生效的原生颜色；主机软件 LUT 不能替代该持久化要求。

2026-09-20 的记录保留了首次安装后 A7R II 黑屏循环重启的事故。随后停止安装及机身写入，保留事故 APK、安装记录和暂停标记。

离线检查发现：原 APK 的 `layer-list` 图标会形成 LayerDrawable，而 4.01 启动器相关方法直接把它强转为 BitmapDrawable。这是明确的兼容缺陷。安装进度到 100% 后的最终会话也没有得到确认，因此安装状态与重启同步是另一条待查线索。缺少故障机崩溃日志，不能把图标当唯一根因，也不能说修图标就一定恢复。

- 安装标记控制同步清理；扫描失败、标记删除失败、设置异常和进程中断各有不同路径。

这里的“重启”是重新建立对象并读回序列化状态，不是实际 Android 冷启动。后续完整 QEMU 目标保留，局部方法实验不能替代它。

## 5. 2026-10-23：GPU 由“缺设备”推进到“缺完成规则”

R12 补入可选的有限时钟/复位控制模型，原 `grm_gles` 驱动加载成功。R13 的只读前端捕获三次一致的实际提交，解包首个 32 字节、四组命令。四组前端检查和六组控制回归通过，仅覆盖相应模型行为。

R14/R16/R17 继续从原程序构造、DMP 调试信息和原驱动中确认：这是一次空工作量的同步提交；128 字节对象为 `dmp_error_tex_buffer_id`，具有备用纹理与虚读引用，不能写一个猜测的完成标志。等待失败后返回 0 还可能进入重试；软件 fence 和回调是完成消费者，无法给出硬件生产完成的条件。

PICA 的 54 个系统寄存器位置以及部分状态位提供交叉线索，但 Sony 的部分命令语义不同。SMAPH-H 项目也存在地址编码和确认机制差异。没有把其他模拟器的近似完成处理移植为 Sony 规范。

## 6. BOSS 与同代机型：从广泛检索转向原始文件对照

R15/R16 追到原 `lld` 的 NAND 加载、SRAM 设备信息、邮箱与复位握手；暖启动快照中的 52 字节设备信息可以核对，但不能代替程序。尚未取得匹配的 BOSS 载荷及完整加载条件。

R18/R19 追升级脚本和工具：`safe_list.txt` 是运行时生成物；`loader_mpt.tar`、两个 pformat 配置及其程序来源仍未知。4.01、A6000、RX100 V 的已检查用户更新 TAR 目录均未列出相应命名载荷，这只是限定目录清单的阴性结果，不证明程序不存在。

R19/R20 取得官方包中的真实原驱动和库，结果比“年代接近”更具体：

- 三机 GPU 驱动有完全一致的 192 字节中断处理核心及重定位，10 个同名函数相同、18 个 ioctl 请求号相同。
- RX100 V 2.00 的 DMPSUGIRM、EGL、GLES2 三库与 A7R II 4.01 整文件一致。
- A6000 3.21 的六份库与公开哈希清单相符；共同接口可参照，但固定池及池构造条件不同，不能直接换库。
- A6000/4.01 窗口回调布局可互相定位，4.01 的 gralloc 多出特定分支，含义仍待查。

最后一轮有 62 项核心、56 项邻接库静态核查通过。它们是 118 项证据一致性检查，不是 118 项整机功能测试。

## 必须保留的结论修订

| 旧说法或容易产生的误解 | 当前准确表述 |
|---|---|
| Sony 固件不能分析、不能修改，也不存在恢复途径 | 已可进行大量离线分析；其他机型有修改项目。能否恢复取决于故障层和可工作的入口，本机任意变砖恢复未证实 |
| 社区没有 Sony 相机 QEMU | 已找到并使用 BIONZ/CXD90014 实现；完整 A7R II Android 环境仍未完成 |
| `ulogio.bin` 只能外部备份获得 | 已从本版暖启动快照恢复匹配配置，不代表其他缺失输入也可同法恢复 |
| NAND 读回通过，所以安装能持久保留 | 只证明合成介质控制器行为，FTL 与 Android 文件系统仍未通过 |
| GPU 提交/中断处理相同，所以完成机制相同且可用 | 消费者代码相同不补齐硬件事务、缓存与中断生产条件 |
| A6000 同代，可直接复用参数和二进制 | 可作为重要对照，已发现内存池和 gralloc 的真实差异 |
| 接收到缩放 COMP 或编码回调就可以释放全部缓冲 | 缩放、编码接收、图像释放和文件落盘是不同阶段 |

原始失败记录保留，后来的成功只能覆盖同一范围的旧结论，不能抹掉未解决的其他问题。
