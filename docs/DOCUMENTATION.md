# 文档制度

状态：采用。责任归属按维护角色记录；没有指定真人时，由本次变更作者维护，项目维护者审阅，不伪造已任命人员。

## 单一事实来源

| 信息 | 唯一维护位置 | 更新时机 |
|---|---|---|
| 任务ID、状态、依赖、验收、证据引用 | handoff/task-board.json | 开始、阻断、恢复、完成任务时 |
| TODO浏览页 | TODO.md（自动生成） | 修改任务板后运行生成命令 |
| 当前可用、欠项、最新证据入口 | PROJECT_STATUS.md | 每轮交付 |
| 发生过的变化 | CHANGELOG.md | 每次可交付改动，最新置顶 |
| 模块依赖 | config/modules.json | 增删模块/依赖时；同改架构说明与反向测试 |
| 用户操作 | docs/USER_GUIDE.md | 功能、入口、导出格式、限制或恢复方法变化时 |
| 架构决策 | docs/adr/NNNN-主题.md | 架构、协议、持久写入、签名或依赖决策变更时 |
| 第三方来源/许可 | third_party/upstreams.lock.json及NOTICE | 引入、升级、移除组件时 |
| 原始执行证据 | evidence/runs或handoff/runs | 运行时追加，禁止覆盖历史 |
| 远端状态 | docs/GITEE.md | 建库、推送、权限、CI实际变更后 |

文档注册表`config/documentation.json`规定每份维护文档的角色与更新触发条件。历史交接资料及历史运行日志不重新标成当前结果。

## 任务制度

状态：not_started→in_progress→completed；遇明确外部依赖可blocked，恢复后回in_progress；取消写cancelled并说明理由。完成必须满足本任务验收，附真实命令、产物或审查记录。设备任务不能由主机证据完成；不能只填证据路径而未实际执行。

任务保持稳定ID，新增工程任务用Gxx，不复用Txx。Gitee Issue日后引用同一ID；远端Issue/Project是协作视图，未经同步不得成为第二套相互矛盾的状态。没有真实Issue不要写虚构编号或URL。

```sh
python3 tools/docs_check.py --write
python3 tools/cv.py check
```

TODO只能由现有标准库小工具生成；不引入新项目管理框架。统一check检查文档存在、注册责任、维护文档本地链接、任务依赖/循环、完成任务证据引用及TODO同步。该检查不能验证文字真伪、证据内容或人工验收，需要评审。

## 变更闭环

1. 写任务的用户收益、范围、影响模块、验收、恢复策略；查复用台账。
2. 先补必要的失败用例，再改实现；涉及公共契约写迁移兼容说明。
3. 更新说明书、状态、任务板、CHANGELOG；重大决定新增ADR并标记替代关系。
4. 运行匹配改动范围的检查；PR写实际命令/退出码、未验证范围和证据引用。
5. 依照handoff/SESSION_TEMPLATE.md记录中断点。代码和说明同轮交付，不以“之后补文档”宣称完成。

CHANGELOG每条说明行为变化及限制；不把运行日志全文塞进变更记录。ADR写问题、候选、决定、后果、验证与撤销方式，已被替代的ADR保留历史。

## 发布与隐私

本地run日志、构建缓存、SDK、钥匙、用户样片默认不入Git。对外只提交经核查的摘要与必要脱敏证据；私有仓库也不上传密钥或个人照片。原片和颜色作品许可由用户决定。

文档缺陷按普通缺陷处理。每个里程碑检查README/说明书/状态是否一致、链接是否有效、未实现能力是否被误述、远端权限和CI是否实际生效。版本分别记录工程、相机Manifest和Studio，不合并成一个完成度数字。
