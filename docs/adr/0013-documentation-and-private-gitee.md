# ADR 0013：文档随代码维护，任务单一来源，Gitee私有托管

日期：2026-09-19。状态：采用；远端建库待账户接入。

## 问题

已有模块和交接资料，但README仍描述没有APK；任务板只有JSON/长任务簿；缺面向使用者的统一手册、文档同步检查和本地Git仓库。文档存在不表示制度落实。

## 决策

复用现有task-board.json作为唯一任务状态源，使用Python标准库生成TODO并检查同步；注册维护文档的角色/触发条件和本地链接。保留现有CHANGELOG/ADR/模板，补说明书、索引、文档制度、Gitee接入记录。新增少量工程检查而非建立另一个文档站、数据库或项目管理服务。

保持模块化单体；config/modules.json与逐模块编译继续约束依赖。补全限定类名绕过、portable IO引用Android、生产模块依赖desktop/test及编译次序反向测试。架构检查中的残余无条件Backup禁令改为调用现有精确profile检查，仍默认禁止所有未经批准写入；避免两套规则互相矛盾。

用户将托管方向从GitHub改为Gitee私有。准备Gitee模板，保留GitHub配置但不自动镜像；CI调用同一个cv.py，不宣称Gitee会运行GitHub Actions。未知账户、Git署名、远端权限和执行器保持未配置。

## 验证和代价

统一check增加文档合同与反向测试；SDK构建验证模块检查改动仍允许现有API10源码。静态检查是词法辅助而非完整Java解析器；不能证明线程/资源或硬件正确性。原始证据保存在本机并排除Git，分享前审阅摘要。

新增文档有维护成本，因此同轮修改、生成视图和检查失败共同约束。回退可撤销新增文档/检查并保留运行证据；不回退用户的私有托管授权，不更改相机业务行为。
