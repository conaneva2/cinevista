# ADR0016：先建立可验证的虚拟相机环境

日期：2026-10-23。状态：采用。

## 问题与用户决定

用户明确把虚拟模拟器作为第一步：仿 A7R II 后背交互，以有依据的 CPU、RAM 和存储约束运行固件，最终用于应用安装/启动和故障复现，避免反复损坏真机。继续禁止操作相机和绕过原断言。该研发顺序优先于 ADR0014 的当前执行次序；实时反挤压可行性和原生颜色要求均保留。

## 候选与决定

继续复用已有 ma1co QEMU CXD90014 模型及原版 4.01 固件，按原启动顺序补齐依赖。普通 Android 模拟器不能替代 Sony 驱动和启动器；单纯网页皮肤也不算固件仿真。为便于操作，加入标准库本地 HTTP 控制台，按钮启动固定、限时、输入锁定的真实实验；界面明确标出尚未接入的原生显示、输入和 APK 能力。

先固定已证实的内存布局和资源上限。未知 CPU 主频、完整 NAND 容量、其他核心职责及图形时序保持未知；不以任意限速宣称硬件等效。持久存储、应用生命周期、故障注入和跨重启验证是后续独立门槛。

## 结果、验收与撤销

本轮恢复日志配置、DMM 和 gl_common 创建关卡，并交付开发操作台。完整 Android 和应用验证未完成。原版断言保持启用，异常是实验结果，不被 UI 当成成功。QEMU 无设备直通，原始固件/APK不改，不触碰相机。

控制台验收：真实启动/停止、错误状态保留、输入漂移拒绝、页面操作、禁用未就绪 APK 入口。总体目标验收仍要求真实固件显示/输入、Android 和持久安装流程。恢复方式是停止本地实验进程并回到既有命令行实验，不删历史证据。源代码改动与固件材料分离，私有固件/日志不发布。
