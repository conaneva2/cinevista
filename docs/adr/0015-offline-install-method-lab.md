# ADR0015：安装启动实验先建立固件方法回放层

状态：采用，2026-10-22。只约束离线实验，不替代 ADR0014 的实时反挤压门槛。

## 问题

用户要求以 4.01 和事故 APK 复现图标、安装中断、重新进入同步的问题，同时明确不操作相机。现有 aapt 门禁只检查包，不能执行固件控制流。本机没有完整 Android/ARM 模拟运行环境。

## 候选与决定

复用 aapt 30.0.3、baksmali 2.5.2、本地固定 Sony-PMCA-RE、Python unittest。对有限固件方法增加小型、拒绝未知行为的指令回放器，外部服务使用明示适配器，JSON 持久化条件状态。依赖输入固定 SHA-256，不生成可安装 APK，不改生产源码。

普通 Android 模拟器缺 Sony 服务；OpenMemories-Framework 是接口替身，不能代替真实固件。社区 ma1co/qemu 的 CXD90014 板型为后续底层模拟候选，OpenMemories-CI 当前核验的样例是 RX100M5 更新环境，不是本机完整系统。先不下载或编译大型工具链，不为了运行界面伪造硬件服务成功。

## 后果与验证

方法分支、调用顺序与异常控制流可以复查；文件、Settings、扫描、资源膨胀和 Binder 只验证适配器条件。没有执行完整 APK 或启动真实 Android，不能宣布物理重启/变砖原因已复现。未知指令/API、错误解析、缺失或变化的输入均停止；故障注入与观察事实分别记录。

20 个方法案例、4 个 PMCA 循环案例已运行；基础语义与拒绝边界有主机测试。通过含义为“与预期分支相符”，不提升设备兼容等级。证据见 `handoff/runs/20261022T075951Z-install-boot-lab/`，使用范围见 [实验说明](../INSTALL_BOOT_LAB.md)。

## 撤销

移除这层独立宿主工具及其锁文件/测试，不影响生产模块。未来若完整 Android/板级环境可运行，应保留这些小型负例作回归，并另行记录硬件/系统覆盖，不能静默扩展当前结果含义。
