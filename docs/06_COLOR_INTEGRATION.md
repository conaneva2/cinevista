# 06｜Recipe Lab 接入契约

## 采用范围
Recipe Lab的MIT许可允许在保留声明的条件下复用。采用指定上游提交中的配方数据和已理解的运行时参数映射；不整包复制MainActivity、不引入Backup持久化写入、未知PP槽、解锁工具或不明素材。[S04]

本版已设置许可与来源台账，但 `included_code=false`；配方、ColorAdapter及UI尚未并入代码。不要把许可证文件的存在写成“77款胶片已支持”。

## 数据与行为分离
配方目录为纯数据：recipeId、upstreamId/commit、name、style、WB/AB/GM、contrast/saturation/sharpness、DRO、PictureEffect、matrix需求、曝光建议、format限制。上游数值/名称只在数据导入器中解释，不让整个应用依赖上游Java类或索尼整数槽。

Adapter先读机身supported-values/已验证映射，再生成EffectiveColorPlan。每个参数记录 requested、supported、applied/readback；机身返回值不等于像素已稳定，需要配方切换靶和样片确认。必需参数不支持则拒绝完整配方；经用户知情的近似版有独立标志和版本，不能静默钳位后沿用“完全相同”名称。

GM轴方向、白平衡单位、DRO枚举、PP互斥、RAW限制以具体上游执行逻辑和机身实测为准，不直接按注释猜符号。不复制A6000的存储索引到A7RII。

## 摄影行为
- 默认不替摄影师改曝光。配方EV是建议；采用时明确开关并冻结；不采用时记录为适配策略。
- PictureEffect要求JPEG-only时提示冲突，不暗中关闭RAW。可先隐藏不兼容配方。
- 保留当前相机色彩为可选项；App临时修改值按所有权恢复，别恢复整包旧参数覆盖用户刚改的曝光。
- 退出时无Backup写入并不证明系统不会持久化，运行时自动持久化要机测。
- 胶片外观由相机生成源JPEG，再做裁切/反挤压。不对已带配方的JPEG再套同一颜色造成叠加。
- RAW不烘焙JPEG颜色，但曝光影响可能改变实际RAW记录；预览/元数据也可能携带外观信息。
- 点击新配方后显示应用/稳定中；在可验证稳定条件前锁定或明确处理快门，不靠任意短sleep声称完成。上游settle-delay仅为研究起点。

## 对外名称与授权
保留Recipe Lab来源与原作者版权；胶片/相机品牌名称用于描述近似外观，不使用他人logo、不宣称官方联名/精确色彩科学。代码开源授权不自动涵盖商标或所有样片素材。

## 接入顺序
原相机外观→一个RAW兼容且普通参数的配方→带WB/偏置代表项→特殊矩阵/PE仅经验证后开放。用少量代表案例验证完整链路，再导入剩余目录。镜头倍率、输出画幅、配方三维组合测试；颜色功能不能代替实时反挤压研发。
