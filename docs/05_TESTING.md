# 05｜测试与证据规范

## 测试层次
| 层 | 测什么 | 不证明什么 |
|---|---|---|
| 静态规则 | 模块依赖、平台类位置、规范文件、Actions锁定 | 动态调用安全、真实硬件行为 |
| 主机逻辑 | 65:24/2.39/AUTO、倍率、偏移、映射、捕获状态、路径安全 | Sony图像引擎、取景速度 |
| 主机像素 | 人工靶真实JPEG解码、变换、编码与原片hash | A7RII机内速度/颜色/分辨率 |
| SDK构建 | API10类型/资源、DEX035、签名与包内容 | 驱动接口实际可用 |
| 设备契约 | 相机生命周期、回执、帧数据、缩放与原生编码 | 其他机身与固件兼容 |
| 摄影验收 | 所见即所得、对焦、颜色、等待、成片体验 | 全面统计性能保证 |

现有Java AllTests为继承的轻量回归入口，不继续扩展成自研测试框架。网络依赖流程建立后优先转入成熟JUnit主机测试框架并保留原案例；测试库绝不打入APK。Python项目规范测试使用标准库unittest。固定版本、许可与下载校验未齐时不编造“JUnit已接入”。

## 新增规则必须有反例
本轮tools负向测试会故意插入：core依赖Android/文件层、UI私有Sony类名、桌面依赖泄露、循环依赖、未固定Actions、密钥文件等；检查器应失败。它们是在临时副本中进行，不污染工程。没有反例的“静态检查通过”不能证明规则真正生效。

## 必须保留的摄影用例
- 普通镜头1×不改变物体比例；真实65:24不是2.70。
- 同一镜头倍率，在AUTO和固定画幅只改变裁切，不改变人物胖瘦。
- 四角不对称标记证明不是仅中心看似相同；移框与输出范围一致。
- LCD/EVF分别测实际显示比例；对焦放大退出不能改变CaptureIntent。
- 配方快速A→B切换后立即拍摄不能串色；requested/applied/readback/effective状态分开。
- RAW+JPEG分组、一快门一意图、迟到回执、重开App、无卡/满卡/取消/编码错误。
- EXIF1–8支持的必须正确；未支持的明确拒绝。ICC/AdobeRGB不能直接重标sRGB。
- 原片hash不变，已有目标不覆盖，临时文件失败可清理且不删有效结果。

## 性能是实测，不是给线程数取名字
记录机身/固件/格式/镜头/卡/显示输出/场景。统计内容更新率而非UI循环；按同一光学事件比较延迟并给原生基线。导出耗时、拍摄恢复时间、内存高水位与失败样本分别记。p50/p95只在有足够真实重复样本时计算，样本少就逐条报告。

最初探索目标沿用v0.1：争取≥24fps内容更新、相对原生增加≤100ms、比例整数误差≤0.1%、构图边界误差≤0.5%。这些是目标，不是已达结果；低照度、不同放大/显示条件可能改变结果。

## 证据状态
`declared`必须有源码签名/资料；`probed`需要本次真实调用结果；`verified`必须有完整条件、预期、实际、日志与输入/输出。接口存在、mock通过、人工图片、语法解析分别标注，禁止合并成相机通过率。

日志包含任务ID、有效参数、耗时、错误类别；默认不含完整用户路径、序列号、Wi-Fi信息、照片或EXIF位置。允许用户主动选择额外诊断，但要预览并确认。

当前能力与v0.3本轮运行记录见PROJECT_STATUS.md和evidence；不要复制上一版PASS日志当新版本结果。
